# cc internal ABI

This is the calling convention used by code generated by `bin/cc`.  The core
scalar, floating-point, aggregate and variadic rules follow the RISC-V LP64D
ELF psABI.  `-c` emits standard ELF64 `ET_REL` objects; the legacy CCO2 format
is still readable for compatibility.  The runtime helper names remain private.

The compiler is a freestanding toolchain: generated programs normally do not
link `libc.a`.  When they do, they must use the same standard ABI as the
GCC-built libc.

## 1. Scalar representation

- integers and pointers: XLEN (64-bit)
- `float`: IEEE-754 single, `fa` register or one 8-byte stack slot
- `double`: IEEE-754 double, `fa` register or one 8-byte stack slot
- `long double`: currently represented as `double`; 128-bit IEEE quad support
  is a remaining psABI item
- `char` is unsigned by default; `signed char` is explicit

## 2. Integer and floating-point arguments

The integer and floating-point register sequences are independent:

- integer/pointer arguments use `a0`..`a7`;
- named `float`/`double` arguments use `fa0`..`fa7`;
- a named floating-point value uses FP registers only when its whole FP
  register group is available.  Otherwise it is passed according to the
  integer calling convention, i.e. as raw bits in `a0`..`a7` or on the
  stack.  A ninth named `double` therefore uses `a0`, not `0(sp)`;
- the integer convention may split a two-word aggregate when only one integer
  register remains: the first word goes in the register, the second on the
  stack;
- arguments that do not fit in their register sequence go on the caller
  stack at `0(sp)`, `8(sp)`, ...;
- the stack pointer is 16-byte aligned at every call.

For a variadic function, the named arguments follow the normal rule.  Every
variadic argument, including `float`/`double`, uses the integer sequence
(`a0`..`a7`, then the stack); the bits are read by `va_arg`.

`long double` is not yet 128-bit, so it is not interoperable with GCC-built
libc objects that use `long double` varargs.

## 3. Aggregates

Small aggregates are flattened into leaf fields and classified as follows:

- an aggregate larger than 16 bytes, or with an unaligned/oversized field, is
  passed by reference (pointer to a caller copy);
- an aggregate with more than two leaf fields uses the integer convention:
  its bytes are packed into one or two integer registers/stack slots (this is
  what GCC does for `{float,float,float}`, float arrays and large integer
  arrays);
- an aggregate with at most two leaf fields and no floating fields packs into
  integer registers by eightbyte;
- an aggregate with at most two leaf fields and only floating fields uses one
  `fa` register per field, provided all of those FP registers are available;
  otherwise the whole aggregate falls back to the integer convention;
- a two-field mixed aggregate uses one integer and one `fa` register in field
  order, e.g. `{float,int}` -> `fa0,a0`, `{char,double}` -> `a0,fa0`,
  provided both an FP and an integer register are available; otherwise the
  whole aggregate uses the integer convention.

Aggregate returns use the same classification: small aggregates return in
`a0/a1`, `fa0/fa1`, or a combination; larger aggregates use a hidden result
pointer in `a0` and return that pointer.

## 4. Function calls

For a call with `n` argument words and an indirect callee:

1. `total = align_to((stack_words + register_words + indirect) * 8, 16)`.
2. `push_reg(s1)`; `sp -= total`; `s1 = sp`.
3. Store stack argument words at `s1 + 0..`; store register argument values in
   the temporary slots after them.
4. Evaluate arguments right-to-left.  Aggregate arguments are copied to their
   parser-provided local temporary; aggregate-by-reference arguments pass the
   temporary address.
5. Load `a0`..`a7` and `fa0`..`fa7` from the temporary slots.
6. For an indirect call, load the target into `t2`.
7. `sp = s1`; `jal ra, target` or `jalr ra, 0(t2)`.
8. `sp = s1 + total`; `pop_reg(s1)`.
9. Scalar return values are in `a0` (integers/pointers) or `fa0`
   (`float`/`double`).  Small aggregate returns are copied from the return
   registers into the call's hidden local temporary; the address of that
   temporary is the internal expression value.  Large aggregate returns use
   the hidden pointer.

Generated functions preserve `s0` and `s1`; they do not use `s2`-`s11` or
`fs0`-`fs11`.  `gp` and `tp` are not modified.  The runtime helpers do not use
`s1`.

## 5. Frame layout

At function entry `sp = old_sp`.  The prologue allocates a frame and sets:

```text
s0 + 0..56   saved a0..a7 for va_list
s0 + 64      caller stack argument 0 (old_sp)
s0 - 8       return address
s0 - 16      caller's s0
s0 - 24      caller's s1
s0 - 32      first local object (grows down)
```

The frame size is `locals_size + 64`, rounded to 16 bytes.  `s0` is
`old_sp - 64`.  The epilogue restores `ra`, `s1` and `s0`, sets `sp =
s0 + 64`, and returns.

## 6. Variadic functions and va_list

`va_list` is a pointer to the contiguous saved argument area:

- the prologue saves `a0`..`a7` at `s0 + 0..56` for a variadic function;
- `va_start` points at `s0 + first_named_integer_slot * 8` when a named
  integer slot is still available, otherwise at
  `s0 + 64 + named_stack_slots * 8`; a named floating-point argument that
  fell back to the integer convention consumes an integer slot;
- stack arguments follow at `s0 + 64`;
- `va_arg` consumes 8-byte slots, with 16-byte alignment for a future
  128-bit `long double`;
- `va_copy` copies the pointer; `va_end` is a no-op.

`usr/include/stdarg.h` uses the GCC-style `__builtin_va_list` / builtins with
the same pointer representation.

## 7. Bit-fields

The current bit-field layout is the compiler's private layout: LSB-first in a
storage unit, no field crossing a storage-unit boundary, and zero-width fields
forcing alignment.  This is not yet guaranteed to match GCC's psABI layout for
unusual mixed base types.

## 8. Relocatable object format

`cc -c` writes a standard ELF64 little-endian RISC-V `ET_REL` object:

- `e_machine = EM_RISCV`, `e_flags` selects the LP64D double-float ABI;
- sections: `.text`, `.data`, `.bss`, `.rela.text`, `.rela.data`, `.symtab`,
  `.strtab`, `.shstrtab`;
- relocations: `R_RISCV_HI20`/`R_RISCV_LO12_I` for address materialization,
  `R_RISCV_JAL` for calls, and `R_RISCV_32`/`R_RISCV_64` for initialized
  data pointers;
- a `.riscv.attributes` section with `Tag_RISCV_stack_align = 16` and an
  `rv64i2p1_m2p0_f2p2_d2p2` architecture string;
- the section header table is present, so GNU `readelf`/`objdump` and
  `ld -r` consume the objects directly.

Linker relaxation is not emitted.

The built-in linker also reads GCC-produced ELF objects and static archives,
extracting archive members on demand.  It supports the RVC branch/jump,
`CALL_PLT`, PC-relative HI20/LO12, LO12_S and 32/64-bit data relocations used
by the in-tree libc and libgcc.  The previous private CCO2 and CCO1 formats
remain readable; `--cco2-object` can still write CCO2 for compatibility
testing.

Executables use two `PT_LOAD` segments (read+execute text and read+write
data+bss) with a fixed base of `0x10000`.  Read-only data is currently placed
in the writable data segment.

## 9. Runtime helpers

In freestanding (`-ffreestanding`) mode the linker injects exactly one copy
of:

- `__cc_puts(const char *s)`: write `s` and a newline to fd 1, return 0;
- `__cc_memcpy(void *dst, const void *src, unsigned long n)`: return `dst`;
- `__cc_memset(void *dst, int byte, unsigned long n)`: return `dst`.

These are ordinary generated functions and follow the call sequence above.
Hosted code instead calls the libc `puts`, `memcpy` and `memset`, and the
runtime unit is not injected.

## 10. Startup, builtins and libc

Hosted mode is the default: links add `libc.a` and `libgcc.a` and use libc's
`_start`, which initializes `environ`, calls `main(argc, argv, envp)` and
calls `exit`, flushing stdio.  In `-ffreestanding` mode the linker injects
`__cc_start` instead, which calls `main` and exits with `SYS_EXIT`.

In hosted mode the compiler stops lowering `read`, `write`, `close`, `open`,
`exit`, `putchar` and `puts` to inline syscalls/helpers and emits ordinary
calls to the libc symbols.  `-ffreestanding` keeps the raw-syscall builtins:

- `read`, `write` and `close` map directly to `SYS_READ`, `SYS_WRITE` and
  `SYS_CLOSE`;
- BRK's `SYS_OPEN` entry is `openat(dirfd, path, flags, mode)`, so the
  `open(path, flags[, mode])` builtin is lowered with `AT_FDCWD` in `a0`,
  the path in `a1`, flags in `a2` and mode in `a3` (mode is zero when
  omitted).

`__cc_puts`, `__cc_memcpy` and `__cc_memset` are still injected for
freestanding code and for struct copies/zeroing in hosted code.
