# cc internal ABI

This is the private ABI used by code generated by `bin/cc`.  It is chosen for
implementation simplicity, not for interoperability with the RISC-V psABI.
All compiler-generated translation units, runtime helpers and object files
must agree on it.

## 1. Scalar representation

- integers, pointers, `float`, `double`: one 64-bit slot (8 bytes).
- `float` values are stored in the low 32 bits of the slot; the upper 32 bits
  are ignored by all consumers.  Every load of a float must therefore use a
  32-bit load, and every store a 32-bit store.
- `double` values occupy the full 64 bits.
- All FP arithmetic is performed in the RISC-V FP registers (`f0`/`f1`),
  then moved back to the integer result slot with `fmv.x.w`/`fmv.x.d`.
  This keeps the expression result convention "result in `a0`" uniform.

## 2. Argument slots

Every argument occupies exactly one 8-byte slot, regardless of type:

| argument type | slot contents |
| --- | --- |
| integer / pointer | value |
| `float` | IEEE-754 single bits in the low 32 bits |
| `double` | IEEE-754 double bits |
| struct / union | pointer to a caller-owned copy (by value) |

The first eight slots are passed in `a0`..`a7`.  Slots 8 and later are placed
on the caller stack at `0(sp)`, `8(sp)`, ... in increasing slot order, just
before the call.

For a function returning a struct/union, slot 0 is the hidden result pointer,
and explicit argument `i` uses slot `i + 1`.

Variadic functions use the same rule.  The prologue spills the first 16
incoming slots into the local `va_area`; `va_start` points just past the named
slots.  This supports up to 16 total arguments in a variadic function; larger
variadic calls are outside the supported subset.

## 3. Call sequence

For a call with `n` explicit slots (including the hidden result pointer when
present) and an indirect callee:

1. `total = align_to((n + indirect) * 8, 16)`.
2. `sp -= total`; `s1 = sp`.
3. Evaluate the callee (if indirect), then arguments right-to-left, storing
   each slot at `s1 + slot * 8`.  A slot may hold a pointer to a local copy of
   an aggregate argument.
4. Load `a0`..`a7` from `s1 + 0..56`.
5. For indirect calls, load the callee from `s1 + n * 8` into `t2`.
6. If `n > 8`, set `sp = s1 + 64` so the callee sees slot 8 at `0(sp)`;
   otherwise leave `sp = s1`.
7. `jal ra, target` or `jalr ra, 0(t2)`.
8. Restore `sp = s1 + total`.
9. For an aggregate return, the result address is the local hidden-result
   temporary (also returned in `a0`); for scalars the result is in `a0`.

`s1` is callee-saved by generated functions.  The runtime helpers
`__cc_puts`, `__cc_memcpy` and `__cc_memset` do not touch `s1`.

## 4. Frame layout

At function entry:

```text
s0 + 0     incoming stack argument slots (slot 8, 16, ...)
...
old sp     == s0
s0 - 8     return address
s0 - 16    caller's s0
s0 - 24    caller's s1
s0 - 32    first local object (grows down)
```

`locals_size` starts at 24.  The frame size is `align_to(locals_size, 16)`.
The prologue:

1. saves `ra`, `s0`, `s1`;
2. saves incoming `a0`..`a7` into `va_area` if the function is variadic;
3. for each parameter slot, stores the incoming register or stack word into
   the parameter's local object;
4. for an aggregate parameter, copies from the incoming pointer into the
   parameter's local object;
5. saves the hidden result pointer when the function returns an aggregate.

For a variadic function, the prologue additionally copies up to eight incoming
stack slots from `s0 + 0..56` into `va_area[8..15]`.

## 5. Bit-fields

- Only integer base types are allowed.
- A bit-field is laid out LSB-first in a storage unit of its declared type.
- Fields may not cross a storage-unit boundary; a field that does not fit
  starts a new storage unit.
- `member.offset` points at the storage unit, `bit_offset` is the LSB index
  inside it, and `bit_width` is the field width.
- A zero-width field only forces alignment of the next field.
- Reads mask and sign-extend according to the declared signedness; writes
  perform a read-modify-write of the storage unit.

## 6. Object format CCO2

Little-endian.  Header fields:

```text
u8[4] magic = "CCO2"
u32 version = 2
u32 text_len
u32 data_len
u32 bss_len
u32 nsyms
u32 ndrels
u32 nrelocs
text bytes
data bytes
symbols...
data relocations...
text relocations...
```

Symbol record: `u32 name_len, name bytes, u32 sec, u32 offset, u32 size,
u32 align, u8 defined, u8 is_static`.

Data relocation: `u32 owner_sym, u32 offset, u32 target_sym, u64 addend`.

Text relocation: `u32 offset, u32 kind, u32 target_sym, u64 addend`.

Relocation kinds remain `HI20`, `LO12I`, `JAL`; a linker must reject unknown
kinds and out-of-range results.

## 7. Runtime helpers

The linker injects exactly one copy of:

- `__cc_puts(const char *s)`: write `s` and a newline to fd 1, return 0;
- `__cc_memcpy(void *dst, const void *src, unsigned long n)`: return `dst`;
- `__cc_memset(void *dst, int byte, unsigned long n)`: return `dst`.

These are ordinary generated functions and follow the call sequence above.

## 8. Kernel entry mapping

`read`, `write` and `close` map directly to `SYS_READ`, `SYS_WRITE` and
`SYS_CLOSE`.  BRK's `SYS_OPEN` entry is `openat(dirfd, path, flags, mode)`, so
the `open(path, flags[, mode])` builtin is lowered with `AT_FDCWD` in `a0`,
the path in `a1`, flags in `a2` and mode in `a3` (mode is zero when omitted).
